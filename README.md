# Enderlings (Fabric, Minecraft 26.3)

Replaces the enderman's model with one of four enderling bodies (main / bruiser / lanky / ember).
Each enderman gets one at random, picked from its UUID so it never changes. Client-side only.

## Build
Needs **JDK 25**. Versions follow the official fabric-example-mod for 26.3
(Loom 1.19-SNAPSHOT, Gradle 9.8.2, Loader 0.20.1, Fabric API 0.165.2+26.3) -- bump them in gradle.properties if fabricmc.net/develop lists newer.

    ./gradlew build          # jar ends up in build/libs/enderling-1.0.0.jar
    ./gradlew runClient      # dev client to look at them (/summon minecraft:enderman)

Drop the jar plus Fabric API into your mods folder.

## This was written without being able to compile against Minecraft 26.3
The mesh loading and skeleton animation (`com.enderling.mesh`) have no Minecraft dependency and were run and checked.
The renderer glue (`com.enderling.client`) was type-checked against stand-ins for the 26.x signatures only.
If the first build fails, these are the likeliest spots (send me the compiler output):

| File | Assumption | Fallback |
|---|---|---|
| EnderlingClient | `net.minecraft.world.entity.EntityTypes.ENDERMAN` | `EntityType.ENDERMAN` |
| EnderlingClient | `EntityRendererRegistry.register(type, provider)` still exists | `EntityRenderers.register` via a mixin/accessor |
| EnderlingRenderer | `net.minecraft.client.renderer.rendertype.RenderType(s)` package; `RenderTypes.entityCutoutNoCull(Identifier)` | auto-import / other `entity*` render type |
| EnderlingRenderer | `net.minecraft.client.renderer.state.CameraRenderState` and its `pos` field | |
| EnderlingRenderer | `collector.submitCustomGeometry(PoseStack, RenderType, (pose, consumer) -> ...)` | |
| MeshDrawer | `VertexConsumer` still in `com.mojang.blaze3d.vertex`; `addVertex(Pose,x,y,z)`, `setNormal(Pose,x,y,z)` | |
| EnderlingRenderer | `LivingEntity` fields `yBodyRot`, `yHeadRot`, `walkAnimation`, `deathTime` | |

## Not included (vs the vanilla enderman)
This renderer draws only the body. The carried block, the glowing-eyes layer, the open-mouth screaming pose and the red hurt flash are not drawn.
Teleport particles and sounds are untouched. Dying makes the model fall over sideways.

## Performance
Models are drawn by pushing vertices every frame. Near endermen use ~9-10k quads, beyond 20 blocks ~3.6-5.2k quads (the sculpt is simplified to those budgets) (FAR_DISTANCE in EnderlingRenderer).
A crowd of endermen will cost more than vanilla.

## Regenerating the meshes
`assets/enderling/meshes/*.bin` come from the .bbmodel files via convert.py (copy in `tools/`; run `python3 tools/convert.py <dir of .bbmodel> <out dir> [_lod]`).
The .bbmodel files themselves are generated by `tools/sdf3.py` (body), `tools/ext.py` (hands, feet, claws, simplification) and `tools/mesh.py` (texture, head, export). `sh tools/build_all.sh out` rebuilds everything: `out/hi` = Blockbench models (~52k faces, with skin creases on hands and feet), `out/mod` = the .bin/.png files that go in `assets/enderling/meshes` and `textures/entity`. Needs Python with numpy, scipy, scikit-image, Pillow and pyfqmr.
